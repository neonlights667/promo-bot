# Бот розыгрышей

Telegram-бот на Go для акции из 10 партнерских дней. Выдает промокоды, проверяет подписку на канал и регистрирует участников розыгрыша. Данные хранятся в SQLite.

За каждый активный день пользователь получает один шанс на главный приз. В финале выбираются пять разных победителей, каждый получает два билета. Результаты розыгрышей подтверждает администратор перед отправкой уведомлений.

## Запуск через Docker

Понадобятся Docker с Compose, токен от @BotFather и публичный HTTPS URL для webhook Telegram.

1. Скопировать `.env.example` в `.env`, а `campaign.example.json` в `campaign.json`.
2. Заполнить `.env`:

   | Переменная | Что указать |
   | --- | --- |
   | `BOT_TOKEN` | Токен бота от @BotFather |
   | `WEBHOOK_SECRET` | Секрет для проверки запросов webhook Telegram |
   | `ADMIN_TOKEN` | Токен доступа к API администратора |
   | `WEBHOOK_URL` | Адрес вида `https://your-domain.example/webhook` |

   WEBHOOK_SECRET и ADMIN_TOKEN должны содержать разные случайные строки длиной от 32 символов. Для `WEBHOOK_SECRET` подойдут латинские буквы, цифры, `_` и `-`.

3. В `campaign.json` указать даты акции, партнеров, каналы, ссылки и призы. Добавить бота администратором в каждый партнерский канал.
4. Настроить reverse proxy для перенаправления HTTPS-запросов к `/webhook` на `127.0.0.1:8080/webhook`. Доступ к `/admin/` оставить только локально или через SSH-туннель.
5. Запустить бота:

```sh
docker compose up -d --build
```

При запуске бот регистрирует webhook в Telegram. Проверить состояние сервиса:

```sh
curl http://127.0.0.1:8080/healthz
```

## Настройки акции

В `campaign.example.json` заполнен пример для десяти последовательных дней. Перед запуском заменить его значения своими.

В каждом дне указаны партнер, числовой `channel_id`, ссылка на канал, срок и способ применения промокода. Каждый элемент `prizes` означает один приз для одного победителя. В `claim_instruction` задаются действия для получения приза.

Общие настройки:

| Поле | Назначение |
| --- | --- |
| `timezone` | Часовой пояс, по которому начинается и заканчивается день |
| `rules` | Правила акции для пользователя |
| `consent` | Текст согласия на передачу имени и фамилии |
| `grand_prize` | Главный приз для одного победителя |
| `reserve_count` | Число резервных участников в каждом розыгрыше |
| `claim_hours` | Срок подтверждения приза в часах после уведомления |
| `banner_url` | HTTPS-ссылка на приветственную картинку, можно оставить пустой |

Одинаковые названия партнеров считаются одним партнером. Условия уже запущенной акции менять не следует. Для следующей акции использовать новую базу и конфигурацию.

## Управление ботом

Промокоды загружаются через API администратора. Там же доступны статистика, выгрузка CSV, подтверждение результатов и рассылка.

Ежедневные розыгрыши проводятся автоматически после окончания дня. Участвуют пользователи с проверенной подпиской, которым Telegram API успешно отправил подтверждение регистрации. Дополнительное действие пользователя не требуется. Финальный розыгрыш проводится после последнего дня акции. Если победитель не подтверждает получение вовремя, приз переходит следующему участнику из резерва.

Пользователь может отключить массовую рассылку командой `/stop` и включить ее снова через `/start`. Команда `/cancel` отменяет ввод данных для получения приза.

Все запросы требуют ключ `ADMIN_TOKEN` из `.env`. Примеры ниже для Bash:

```sh
export ADMIN_TOKEN='your-admin-token'
```

Адрес `http://127.0.0.1:8080` используется при запуске на той же машине. Дату в примерах заменить на нужный день акции.

### Промокоды

```sh
curl -X POST http://127.0.0.1:8080/admin/promos/2026-11-01 \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"codes":["FESTIVAL01","FESTIVAL02","FESTIVAL03"]}'
```

Один запрос принимает до 10000 кодов, размер JSON до 1 МБ. Код уникален для всей акции. Повторный импорт в тот же день пропускает уже загруженные коды. Если в списке есть ошибка, весь импорт отменяется.

### Статистика

```sh
curl http://127.0.0.1:8080/admin/stats \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

В ответе: число пользователей, новые пользователи по дням, запросы и выдачи промокодов, остатки кодов и участники ежедневных розыгрышей. Также показаны размеры очередей событий и сообщений, число ошибок отправки.

### Результаты розыгрышей

Посмотреть список:

```sh
curl http://127.0.0.1:8080/admin/draws \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

ID ежедневного розыгрыша совпадает с датой. Для финального используется `final`.

Скачать участников и результаты в CSV:

```sh
curl http://127.0.0.1:8080/admin/draws/2026-11-01/export.csv \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -o results.csv
```

CSV содержит участников, число шансов, победителей, резерв и время проведения розыгрыша. Имя и согласие победителя появляются после подтверждения получения приза.

После проверки результатов подтвердить их:

```sh
curl -X POST http://127.0.0.1:8080/admin/draws/2026-11-01/approve \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Бот отправит уведомления победителям. Повторное подтверждение не дублирует отправку. Подтверждается и порядок резерва: при истечении срока ответа приз автоматически переходит следующему участнику из этого списка.

Если участников меньше, чем призов, победителей будет столько, сколько участников. После исчерпания резерва новый выбор не проводится.

### Рассылка

```sh
curl -X POST http://127.0.0.1:8080/admin/broadcasts \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"id":"day-2-reminder","text":"Сегодня новый партнер. Заходи участвовать!"}'
```

Для каждого нового сообщения задавать свой `id`. Повторный запрос с тем же ID и текстом не создает новую рассылку. Пользователи, отправившие `/stop`, исключаются из массовых сообщений. Уведомления о выигранных призах отправляются независимо от этой настройки.

### Ошибки отправки

Посмотреть последние 100 ошибок:

```sh
curl http://127.0.0.1:8080/admin/messages/failed \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

При HTTP 400 приз остается за победителем, а срок получения еще не начинается. Администратор может исправить текст и повторить отправку:

```sh
curl -X POST http://127.0.0.1:8080/admin/messages/123/retry \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"text":"Исправленный текст уведомления о призе"}'
```

Вместо `123` указать ID сообщения из списка ошибок. Для отправки прежнего текста передать `{}`. Кнопка получения приза сохраняется. Повторить уведомление можно, пока приз ожидает первоначальной отправки.

При HTTP 403 пользователь недоступен боту, поэтому приз переходит резервному участнику. Временные ошибки бот повторяет сам; при ограничении частоты отправки учитывает задержку, которую вернул Telegram.

## Запуск без Docker

Нужен Go 1.26. Передать переменные из `.env` в окружение терминала и выполнить:

```sh
go run ./cmd/bot
```

Само приложение файл `.env` не читает. По умолчанию используются `campaign.json`, база `data/bot.db` и адрес `127.0.0.1:8080`. Их можно изменить через `CONFIG_PATH`, `DB_PATH` и `LISTEN_ADDR`.

Без `WEBHOOK_URL` бот запускается, но не регистрирует новый webhook. Это позволяет настроить доставку событий отдельно.

## Данные

Запускать один экземпляр бота. В Docker база хранится в volume `bot-data` и сохраняется при перезапуске контейнера. Для резервной копии можно остановить контейнер и скопировать весь volume. Копировать только файл базы во время работы не следует: часть данных может находиться в файле WAL рядом с ним.

Повторные события Telegram не создают новые заявки, промокоды или шансы. Если соединение прервется после отправки сообщения, но до сохранения результата в базе данных, уведомление может быть отправлено повторно.

## Проверка

```sh
go test ./...
go vet ./...
go build ./cmd/bot
```

Для тестов токен Telegram не нужен. Они используют временные базы SQLite и имитацию Telegram API. В GitHub Actions также запускается `go test -race -cover ./...`.
